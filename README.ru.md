# hwid-relay

**Подключайте сколько угодно устройств к панели с лимитом HWID — все они будут считаться одним устройством.**

Самостоятельно размещаемый релей на Cloudflare Workers (бесплатный план). Приложения подписываются на релей; релей скачивает настоящую подписку с одним фиксированным идентификатором устройства. Панель видит одно устройство — сколько бы телефонов, ПК или телевизоров вы ни подключили. Работает со стоковыми приложениями: Happ, v2RayTun, Streisand, Karing, FlClashX и любыми другими, загружающими подписку по URL.

## Как это работает (30 секунд)

Панели вроде [Remnawave](https://docs.rw/features/hwid-device-limit) считают уникальные значения заголовка `x-hwid` на пользователя. Каждое приложение генерирует своё значение и не позволяет его изменить — поэтому десять приложений становятся десятью устройствами.

Релей меняет точку подключения приложений:

![Архитектура hwid-relay: много устройств — один HWID на панели](docs/architecture.svg)

## Пошаговая инструкция

### Перед началом

Нужно:

1. **Ваша текущая ссылка подписки** — адрес панели с личным токеном, например:
   `https://panel-provider.com/sub/6f9a2b1c-4e7d-4c1a-9b2e-8f5d3a7c1e2f`
   Если есть только зашифрованная ссылка `happ://crypt5/...` — сначала расшифруйте её через [happ-decryptor](https://github.com/cylaro/happ-decryptor).
2. **Бесплатный аккаунт Cloudflare** — [dash.cloudflare.com](https://dash.cloudflare.com) → Sign up. Карта не нужна.
3. **5 минут.**

### Шаг 1 — Разверните воркер

1. Нажмите кнопку **Deploy to Cloudflare** выше (или создайте воркер вручную: dash.cloudflare.com → **Workers & Pages** → **Create** → **Create Worker**).
2. Задайте имя, например `hwid-relay`, и завершите деплой.

Теперь у вас есть воркер по адресу `https://hwid-relay.<ваш-поддомен>.workers.dev`.

### Шаг 2 — Соберите ссылку для устройств

Ссылка устройства = адрес воркера + ваш секрет + **полный URL панели**:

```
https://your-worker.workers.dev/<secret>/s/https://panel-provider.com/sub/6f9a2b1c-4e7d-4c1a-9b2e-8f5d3a7c1e2f
                               └──────────── секрет ────────────┘ └──────────────── URL панели ───────────────┘
```

Вместо этой панели можно подставить любую другую — релей запросит её с вашей фиксированной идентичностью. Домены ограничиваются переменной `ALLOWED_HOSTS`, если планируете делиться ссылкой.

### Шаг 3 — Выберите идентичность устройства

Эти значения панель будет видеть как «устройство»:

| Поле | Правило | Пример |
|---|---|---|
| `HWID` | 10–64 символа: `A-Z a-z 0-9 = -` | `UE42LJXu4DbiCaBv` |
| `USER_AGENT` | любая строка, лучше как у реального клиента | `Happ/1.16.0 (iOS 18.3; iPhone 14 Pro)` |
| `DEVICE_OS` | `iOS`, `Android`, `Windows`, `macOS`… | `iOS` |
| `VER_OS` | версия ОС | `18.3` |
| `DEVICE_MODEL` | название устройства | `iPhone 14 Pro` |

Случайный корректный HWID генерирует редактор [happ-decryptor](https://github.com/cylaro/happ-decryptor) (кнопка `+ HWID`). Выбрав значения, **больше их не меняйте** — панель помнит устройство по ним.

### Шаг 4 — Задайте переменные воркера

В панели Cloudflare:

1. **Workers & Pages** → `hwid-relay` → **Settings** → **Variables and Secrets**.
2. Добавьте каждую переменную ниже с типом **Text** и в конце нажмите **Deploy**:

| Имя | Значение |
|---|---|
| `HWID` | `UE42LJXu4DbiCaBv` |
| `USER_AGENT` | `Happ/1.16.0 (iOS 18.3; iPhone 14 Pro)` |
| `SECRET_PREFIX` | случайное слово, например `hX7kQ2mV` |
| `DEVICE_OS` | `iOS` |
| `VER_OS` | `18.3` |
| `DEVICE_MODEL` | `iPhone 14 Pro` |

Сохранение переменных автоматически пересобирает воркер.

### Шаг 5 — Проверка здоровья

Откройте:

```
https://hwid-relay.<ваш-поддомен>.workers.dev/hX7kQ2mV/health
```

Ожидаемый ответ:

```json
{"status":"ok","hint":"subscription URL: <worker>/SECRET_PREFIX/s/<token>"}
```

Если ответ `{"status":"misconfigured",...}` — в нём перечислено, каких именно переменных не хватает или какие неверны.

### Шаг 6 — Убедитесь, что панель приняла идентичность

Откройте в браузере:

```
https://hwid-relay.<ваш-поддомен>.workers.dev/hX7kQ2mV/s/6f9a2b1c-4e7d-4c1a-9b2e-8f5d3a7c1e2f
```

Вы должны увидеть содержимое подписки (текстовый список `vless://...`, Base64 или подобное). Это доказательство, что панель приняла ваш HWID — релей всегда отправляет именно эти заголовки.

Загляните также в карточку пользователя на панели (сайт или мини-приложение провайдера): в списке устройств должно появиться **одно устройство** с вашим `DEVICE_MODEL`.

Альтернативная проверка: [happ-decryptor](https://github.com/cylaro/happ-decryptor) → вкладка Request → отправьте URL панели с теми же значениями и посмотрите заголовки ответа.

### Шаг 7 — Подключите устройства

В каждом приложении (Happ, v2RayTun, …) добавьте подписку по URL:

```
https://hwid-relay.<ваш-поддомен>.workers.dev/hX7kQ2mV/s/6f9a2b1c-4e7d-4c1a-9b2e-8f5d3a7c1e2f
```

Готово. Обновите подписку на всех устройствах — на панели по-прежнему одно устройство. Отображение трафика тоже работает (`subscription-userinfo` пробрасывается).

> **Не публикуйте ссылку на релей публично** — любой, у кого она есть, будет расходовать ваш трафик под вашей идентичностью.

### Обслуживание

| Событие | Действие |
|---|---|
| Провайдер выдал новый токен | Подключите устройства по новой ссылке с новым токеном |
| Провайдер переехал | Используйте ссылки с новым адресом панели — устройства не трогайте |
| Хотите другую идентичность | Измените `HWID`/`USER_AGENT`, затем обновите подписку на всех устройствах |

## Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| `/health` возвращает `{"status":"misconfigured","missing":[...]}` | Переменная отсутствует или неверна | Исправьте перечисленную переменную (шаг 4) |
| Подписка открывается, но в заголовках `x-hwid-max-devices-reached: true` | Лимит уже занят ранее добавленными устройствами | Удалите старые устройства в карточке пользователя на панели или попросите владельца поднять лимит |
| Панель отдаёт 404 или пустое тело | Неверный токен, провайдер блокирует IP Cloudflare, либо панель требует идентичность, которую вы не настроили | Откройте исходную ссылку панели в браузере; если там работает — сверьте переменные; если провайдер блокирует дата-центры — релей на Cloudflare не поможет |
| От воркера `Not Found` | Неверный путь или `SECRET_PREFIX` | Используйте точно `<worker>/<SECRET_PREFIX>/s/<token>` |
| В приложениях не отображается трафик | Панель не отправляет `subscription-userinfo` | Сторона панели, к релею отношения не имеет |

## Честные ограничения

- Панель видит одно устройство, запросы которого приходят с IP-адресов Cloudflare с высокой частотой. Провайдер может заметить это в логах сервера; использование против условий тарифа — ваше решение.
- Если провайдер блокирует IP дата-центров, релей не поможет — ни один бесплатный публичный сервис это не исправит.
- Один воркер = одна панель + одна идентичность. Несколько панелей → разверните воркер несколько раз (или используйте полные URL панелей в ссылках — домены ограничиваются `ALLOWED_HOSTS`).
- Ответы больше 2 МиБ (по Content-Length) отклоняются; запросы к панели прерываются через 15 секунд.
